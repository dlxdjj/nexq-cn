# NexQ 中文助手

基于 NexQ 的非官方 Windows 中文定制版，面向英文线上会议、课程交流和口语练习：在悬浮窗口中查看对方英文原话、中文翻译、可直接说出的英文建议回复及其中文翻译，并按配置检索上传的参考资料。

当前应用版本：**2.20.13-cn.4**（原生安装版本号为 `2.20.13`）。本仓库保存源码，不包含个人 API Key、会议记录、用户资料库或本机安装包。

> 本项目不是 Teams 官方插件，不会自动替你发言或发送消息。它通过本机麦克风与系统回环音频工作。云端语音识别和大模型会接收相应音频、文本或检索片段，不能称为“所有数据完全离线”。请在获得必要许可、符合会议或课程规则的情况下使用。

## 相比上游修改了什么

### 1. 中文界面与双语会议流程

- 中文应用名、安装向导、托盘及主要界面文案；独立应用标识 `com.nexq.zhcn`，避免与原版配置混用。
- 对方问题以英文原话和中文翻译显示；回复面板显示本次回答的问题、推荐英文回复及中文译文。
- 支持自动回复开关、手动对指定问题生成回复，以及可展开的知识库检索依据。
- 修复主窗口与悬浮窗之间的会议状态、快捷键和监听职责，减少重复触发。
- 禁用上游自动更新入口，防止中文定制版被原版安装包覆盖。

主要界面已中文化；部分高级设置、第三方服务名称和运行时错误可能仍有英文，并非所有界面文字都经过完整中文验收。

### 2. 我方/对方与长段讲话处理（cn4）

- 线上会议优先按音频通道标识“我方”和“对方”，不再让两个通道相同的 `speaker_0` 都显示为“发言者 1”。
- Whisper 的网络上传分片与界面上的完整话轮分离：连续讲话累计更新同一条字幕，结束后再提交完整问题。
- 采用约 4 秒音频批次和 250 ms 重叠，减少硬切片边界影响；话轮结束遵循语音设置中的停顿阈值。
- 收到完整对方问题后才自动回答，避免对每个中间片段都作答；对长话轮中的简短我方插话不再直接误判为已经回答。
- 结束会议时取消未完成任务；队列溢出或识别错误时不把缺损内容伪装成完整话轮自动回答。

这里的“我方/对方”是**音频来源区分，不是多人声纹识别**。对方有多个人时，不能据此可靠识别每个人；设备串音也需要从音频设置处理。

### 3. 静音误识别与翻译稳定性（cn4）

- 新增本地自适应能量门控、直流偏移过滤、起声确认和前置音频缓冲，减少静音、短点击和低噪声上传。
- Whisper 使用 `verbose_json`，结合 `no_speech_prob`、`avg_logprob`、`compression_ratio` 过滤可疑结果；仅标点内容不进入字幕、翻译或自动回复。
- 不把真实的 “Thank you” 列为禁词，而是从音频与识别置信信息降低无声时幻觉。
- 长话轮尚未结束时也可更新中文翻译；同一字幕的翻译请求串行并合并待处理更新，旧译文保留到新译文到达。

本地门控不是神经网络人声分类器。很轻的人声可能漏检，强噪声可能误触发，不能保证零误识别。

### 4. 推荐回复更接近“我现在该怎么说”

- “生成回复”和“推荐表达”共用一份第一人称口语提示模板，要求直接给出可说的英文回答，而不是分析“会议记录里没有现成答案”。
- 普通知识或日常问答不强制要求知识库命中；未知个人经历、偏好、业务交期等不允许凭空编造，必要时给出可直接说的条件式回答或澄清表达。
- 迁移未修改过的旧内置提示词，保留用户自定义指令。
- 翻译和连接测试使用独立输出通道，不再混入会议的回复流；修复生成取消、异常释放和并发请求管理。

建议仍需核对事实和真实意愿。提示词约束不等于回答准确率保证，也不能代替个人背景资料。

### 5. 知识库与设置修复

- RAG 设置持久化；校验模型、向量维度和索引配置，更换模型后提示重新索引。
- 使用临时索引和事务发布，构建失败时保留原索引；修复全文索引同步及检索阈值处理。
- 避免把一个相关度很低的“第一名结果”归一化成看似完美的匹配。
- 明确显示未建索引、未命中、检索失败、部分结果与命中状态，以及实际片段和文件来源。
- 设置页面增加真实生成、合成语音转写、翻译和嵌入检查，不仅判断服务进程是否在线；测试可能产生正常 API 费用。
- 移除可能包含密钥的完整服务配置日志输出，使用中文定制版独立的凭据命名空间。

按代码模块查看：[中文定制改动索引](docs/CN-CHANGES.md)。

## 能否用于 Teams

可以采用“线上会议 + 麦克风输入 + Teams 实际播放设备的系统回环”方式使用，不需要机器人加入会议。但本版没有读取 Teams 原生字幕、会议成员身份或官方会议 API，也没有完成所有 Teams/声卡/耳机场景的现场兼容性验收。

使用耳机有助于减少对方声音再次被麦克风采集。若一个声音同时出现在“我方”和“对方”，先检查是否选错设备、启用了立体声混音或存在声学串音。

## 配置与首次使用

以下是本版已验证链路的示例，不是对未来模型可用性或价格的保证；密钥和设置不会随仓库自动迁移到另一台电脑。

1. 安装自己构建或从本仓库可信私有发布获得的 Windows x64 安装包；如果本仓库尚无 Release，请按下节构建。不要用上游 Release 替代中文定制包。
2. 在 LLM 设置中选择 OpenAI，填入自己的官方 API Key。cn4 固定样本验证使用的是 `gpt-4.1-mini-2025-04-14`。保存后运行“测试模型生成”。
3. 在 STT 设置选择 Whisper API（实现使用 `whisper-1`），填写对应密钥，选择英文识别并测试。网页语音识别和 Windows 原生识别仍属于其他服务路径，不是本次长话轮修复的主要验证对象。
4. 实时翻译选择大模型翻译，源语言英文、目标语言中文；它复用配置的 LLM，仍会消耗 API 用量。
5. 线上会议中，“我方”选择麦克风；“对方”选择 Teams 真正输出声音的耳机或扬声器回环设备。停顿阈值可先设 3 秒，较长停顿更利于保留完整问题，但会增加等待。
6. 需要个人资料检索时，运行 Ollama 并单独下载嵌入模型：

   ```powershell
   ollama pull nomic-embed-text
   ollama list
   ```

   在“上下文策略 / Context Strategy”中选择本地 RAG，服务地址使用本机 Ollama 地址（通常为 `http://localhost:11434`），模型 `nomic-embed-text`，对应维度 `768`。测试嵌入后上传 PDF、DOCX、TXT 或 Markdown 资料，构建索引，再用已知答案测试检索。

   Ollama 在这条配置中负责把资料与问题转成检索向量，并不替代 OpenAI 回答问题。只安装 Ollama 或下载模型，**不等于已经建立了个人知识库**。不使用资料库时可不启用本地 RAG。

7. 开启自动回复前，先做一分钟静音、我方单独讲话、对方单独讲话、对方连续长问题的验收；观察标签、完整问题和建议回复是否对应。

## 速度、准确率与已知限制

- 当前是 Whisper REST 短片上传，不是 Realtime/WebSocket 逐字流式转写。音频批次、停顿阈值、网络、转写、检索及生成都会影响总延迟。
- 每个音频通道最多两个在途转写请求，并按音频顺序交付；缓冲有上限。网络过慢发生溢出时需重新开始会议恢复，不能保证网络异常时零丢失。
- 完整话轮后的自动回复仅保留 350 ms 调度防抖，不再重复等待一轮停顿；这不代表端到端响应只需 350 ms。
- 双语翻译与回答会增加请求量。较短但充分的上下文、相关的知识资料与合适的停顿阈值通常是需要现场测试的调优项。
- 不承诺 100% 识别、翻译或回答正确，不承诺所有界面、设备或云服务可用。

## 构建与测试

Windows 构建需要 Node.js 20+、npm、Rust MSVC 工具链、Visual Studio C++ Build Tools/Windows SDK、CMake、LLVM/libclang，以及 WebView2 Runtime。原生音频/ONNX 依赖会增加下载、编译时间与磁盘占用。

```powershell
npm ci
npm run test:cn
npm run build
npm run tauri -- dev
# 生产安装包
npm run tauri -- build --bundles nsis
```

默认安装包输出位于 `src-tauri/target/release/bundle/nsis/`；设置 `CARGO_TARGET_DIR` 时会改变位置。源码保留 `scripts/build-cn.ps1`，用于 Windows 原生测试和打包；工具必须位于 PATH，或通过脚本参数/环境变量指定，详见 [测试说明](tests/README.md)。

cn4 在 2026-09-14 的验收记录：70 项 Rust 离线测试、10 项前端逻辑测试、4 组模拟浏览器测试及生产构建通过。另有显式运行的真实服务测试，使用固定文本和合成语音，不是实际 Teams 通话。LLM 固定样本完整请求约 1.1–3.5 秒、合成语音转写约 3.2 秒；这些不是会议总延迟或性能保证。本仓库整理后未重新执行收费接口测试。

本仓库保留上游网站与发布脚本作为参考，但禁用它们的发布作业，防止首次私有上传自动发布网站或安装包。中文包的上游自动更新亦已停用。
